Studio handbook

How we build a client report.

Written after the first one, for Colorado Girl Coffee. The shape works for anything we send a client on a schedule, monthly numbers, a quarterly review, a project close out. What changes per client is everything except the footer and the discipline.

29 September 2026 · Aster

The one fixed thing

Client on top, studio at the bottom.

The footer is always Neon Burro. Everything above it is always the client's. The shape carries it as well as the colour, the client's letterhead is full bleed and square across the top of the sheet with the corners rounded below, and the studio footer mirrors it, rounded above and square at the foot.

Nothing else is fixed. Palette, photography, which figures lead, how many recommendations, all of that is per client and should look like them and not like us.

The discipline

Three refusals, and they matter more than the design.

A report that looks beautiful and says something untrue costs the client's trust, and it is their staff who see it, not ours. These are worth more than any layout decision in here.

01
A figure we cannot derive gets left out, never estimated
Not zeroed, not dashed, not filled with something plausible. The section does not render and the report says in words why. Colorado Girl's September report carries a block headed two numbers are missing on purpose, and it reads better than a guess would have.
02
Never type a timestamp
It was hand written four times while the first report was built and it was wrong every time, because whoever types it is guessing. Tyler caught it. Render it from an ISO value filled by the row, so the document and the database cannot disagree.
03
The narrative is written by rule, never by a model
Each sentence restates a figure printed beside it, so a reader can check it against the number. Already the law in netlify/functions/_client-report.js and it applies to anything hand written too.

Anatomy

What goes in, and in what order.

Numbers first. A client opens this to find out how the month went, not to read about us. Everything we want from them comes after we have told them something they wanted to know.

  1. CoverClient mark, the period, a title. Nothing else inside the colour band.
  2. Prepared by and prepared forBelow the band, on the client's paper, where it is readable.
  3. The moneyRevenue and labour lead. Anything genuinely unknown is a question mark with a sentence saying why.
  4. What soldTop three each side. This is where data problems surface, and a real one argues better than we can.
  5. The scoreFive measured parts, no judgement. See below.
  6. What shippedBroad strokes with the reason attached. Never a change log, nobody outside the work cares about seven photographs.
  7. Included either wayThe groundwork that needs no approving, so the cheapest tier never feels thin.
  8. Recommendations, in phasesEach with a Why line and three answers. Yes, not this month, let us talk.
  9. The amountFramed as a question, never as a price menu. Be generous, either answer is fine.
  10. What are you thinking aboutOpen, theirs, with a microphone. Tell them not to type.
  11. SubmitOne button, no name field, recipients pre ticked. We know who we sent it to.
The figures

Every number traced to a query.

For a Square client the money section is three calls. Run them against that client's own token and location, never a shared one.

// completed orders in the period
client.orders.search({ locationIds: [LOC], query: { filter: {
  dateTimeFilter: { closedAt: { startAt: BEGIN, endAt: END } },
  stateFilter: { states: ['COMPLETED'] } } } })

// wages, off the timecards
client.labor.shifts.search({ query: { filter: {
  start: { startAt: BEGIN, endAt: END } } } })

// the menu, and how much of it has a photograph
client.catalog.list({ types: 'ITEM' })
Two things learned the hard way

The SDK is v43 and it dropped Client and Environment. It is SquareClient and SquareEnvironment now, and the namespaces moved too, client.orders.search rather than client.ordersApi.searchOrders. Colorado Girl's own netlify functions still import the old names and will throw when they next run.

Wages off timecards are not payroll. No taxes, no employer burden, nobody salaried. Label it wages and say so in the report, or the client reads it as their full cost of staff and makes a decision on a number that is too small.

The score

Five measured parts, averaged in the open.

Colorado Girl's came to 73, not the low eighties that was asked for. The honest number was the better pitch, because seventy three today and ninety in October with one job in between is a story, and eighty two is a shrug. If a part cannot be measured for a client, drop it and average the rest. Never invent a component to fill the shape.

The share card

1200 by 630, client's ground, studio's mark.

Built the way coloradogirlcoffee/scripts/og-cards.mjs builds its own. Set the studio wordmark as one typeset piece and trim it, so the lime period lands where the type puts it rather than where a guessed offset puts it.

magick -background none -fill '#F4F3F1' -font dm-sans-500.ttf -pointsize 25 \
  label:'neonburro' -trim +repage wm-a.png
magick -background none -fill '#C5D957' -font dm-sans-500.ttf -pointsize 25 \
  label:'.' -trim +repage wm-b.png
magick wm-a.png wm-b.png -background none +append wm.png

A card cannot contain a link. A link preview is one image and one destination. The studio mark sits on the card as a mark, and the card itself links to the report. ImageMagick is not on Netlify, so cards are rendered by hand and committed, the same arrangement og-cards.mjs already documents.

The owner's link

No account, no password, one token.

/report/:token/ sits above the ProtectedRoute block in src/App.jsx, beside login and accept invite, which is already proof that Pulse serves pages to people with no session. netlify/functions/report-public.js is the door. Read its header before changing it.

Four refusals in that door

It takes no client id, no report id and no period. The token is the only way in. A door that accepts a row id is a way to read every client's revenue by guessing numbers.

The timestamp is the server's clock, never the request body. A time we rely on to say what work was authorised must not be settable by the person it binds.

First submit wins. A second is refused, because the point of keeping the signed copy is that it cannot change afterwards.

Every failure answers identically. A door that says expired has told an unknown caller they guessed a real one.

Before it goes

The check.

  • Every figure traced to a query, none typed
  • Anything underivable left out, with a sentence saying why
  • Timestamp rendering from an ISO value, not written by hand
  • Footer untouched, client brand everywhere above it
  • Share card rendered and committed
  • Link to Tyler first. Every finished report, before it reaches an owner. No exceptions, including routine months.
